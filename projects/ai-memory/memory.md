## What It Is
The markdown-only memory system for Claude Code — no vector DB, no daemons, no MCP server, just files + hooks + macOS-`bash`-3.2 shell scripts. This is a **meta-project**: the project being tracked *is* the memory tooling. Single owner (Seyi). Authoritative spec is the repo `README.md` (a lean landing page) plus the deep-reference pages under `docs/` — `docs/harnesses/<name>.md` per harness, mirroring the multi-harness direction.

Three layers (Karpathy LLM-Wiki pattern):
- **Schema** — `identity.md` (hard rules, injected once/session), `~/.claude/CLAUDE.md`. Outranks everything.
- **Wiki** — `domain/*.md` (cross-project) + `projects/*/memory.md` (engagement-specific). Durable.
- **Scratchpad** — `projects/*/working.md`, injected with the full payload at session start (re-injected on `@memory`/after compaction) while non-empty — **not** every prompt; matures into the wiki via `/promote-memory`.

Moving parts: one `UserPromptSubmit` hook (the shared `scripts/hooks/inject.sh`, format-parameterized) emits `<memory:*>` blocks; slash commands in `~/.claude/commands/`; scripts in `scripts/` (`_lib.sh`, `regenerate-index.sh`, `lint-memory.sh`, `archive-cleanup.sh`, `new-project.sh`, `memory-pin.sh`, `link-skills.sh`, `executor.sh`, `codex-mem.sh`, the `taskprovider/` package + `taskctl`) with dependency-free bash-3.2 tests under `scripts/tests/`.

## Current State
Functional and in daily use across the real engagements indexed in `index.md`. This checkout is the distributable **source copy**, `origin = seyio91/ai-memory-system` — **public since 2026-07-20**. Channel and all other per-instance choices live in gitignored `config.local.sh` — never described here, since tracked memory ships to every consumer.

The engine is **harness-agnostic** (`install.sh` is a generic manifest-driven installer; `claude`/`codex`/`antigravity` are registered harnesses; the marker is `.agents/memory-project`; the executor resolves roles from the manifest) and **versioned**: consumer instances sync to stable `v*` tags, never to a moving `main`. `v1.0.0` is a trap tag (see Gotchas); `v1.1.0` is the first safe one. The current latest is deliberately **not** recorded here — it rots on every release, and `git tag -l 'v*' | sort -V | tail -1` is authoritative. Design records live in Architecture Decisions below.

## Architecture Decisions
- **Markdown over a DB** — markdown files are the durable store; normal editor, diff, grep, and git workflows are the database interface.
- **Hook-injected, not retrieved** — context is delivered in-band: full payload on session start, `@memory`, and first post-compaction prompt; breadcrumbs otherwise; domain files stay lazy-loaded.
- **Frontmatter-driven catalog** — `index.md` is regenerated from frontmatter inside the `<!-- BEGIN AUTOGEN -->` / `<!-- END AUTOGEN -->` fence; retired fences are ignored, and scaffold files stay out of the catalog.
- **Lean index** — `index.md` lists names and summaries only; paths are derivable, while repo metadata and domain triggers remain in the source files.
- **No per-session marker; `SessionStart` is the once-per-session guarantee** — initial full injection relies on the hook event itself; only compaction recovery uses a per-session sentinel.
- **Compaction recovery** — compaction rehydration is a sentinel handoff from `SessionStart source=compact` to the next `UserPromptSubmit`, which emits the full payload once.
- **Project detection per-prompt** — active project resolution walks up from `cwd` to `.agents/memory-project`; no marker means memory is dormant, with legacy `.claude/memory-project` read only as fallback.
- **Bidirectional repo↔project map** — `.agents/memory-project` is the forward map and `repo`/`repo_path` frontmatter is the reverse map; `repo_path` is relative except the `$MEMORY_DIR` self-reference for `ai-memory`.
- **Distributed cross-project relationships** — related-project knowledge lives where the work starts; sibling work is delegated rather than loaded, and plan-set execution pauses at human or CI gates.
- **Orchestrator / Executor / Validator workflow** — the main session orchestrates, executors implement, and the read-only validator role checks plan success criteria; `todo.md` remains the plan tracker and destructive executor actions stay forbidden.
- **Executor: two roles, manifest-resolved.** `executor.sh` resolves `task` and `explore` through harness manifests and config-local executor settings; read-only roles never fall back to write-capable execution.
- **Task-provider layer + `/task`/`/start`** — tasks are a pluggable, push-dominant projection over local or Notion backends; `/task` captures intent and `/start` turns it into a plan.
- **Task `summary` is a capped thin record; long-form lives in the tree by pointer** — task summaries are capped at 500 characters, while detailed pre-plan material lives as named investigations in the project tree; Notion page bodies are outside the provider contract.
- **`add_progress` stays an unwired no-op — settled WON'T BUILD (2026-07-20).** `contract.py:117` is the only non-abstract method on the provider ABC, and that asymmetry is deliberate: the concrete `return None` is what lets a new backend opt *in* rather than be forced to stub it. **Do not "clean up" the unused method** — it is load-bearing. Not wired to `/checkpoint` because the two don't line up: `add_progress(ref, note)` needs a task ref, while `/checkpoint` is scoped to a project and a session and may cover zero, one, or several tasks. Compounding it, a progress note is neither a capped `summary` nor a page body (which is outside the contract), so Notion has no defined home for one, and checkpoints are high-volume enough to have needed `/checkpoint-archive` — pushing each one outward would be one-directional noise with no reconciliation path. If ever revisited, the live plan's `task_ref` frontmatter is the strongest ref source, since `/plan-archive` already relies on that seam.
- **`design-brainstorm` skill (gated Tier-3 design pass)** — only Tier-3 feature work with open design questions runs the brainstorm pass; its output is folded into the plan, not a separate spec. **Renamed from `brainstorming` on 2026-09-08** to end a live collision with the `superpowers:brainstorming` plugin skill, which the SessionStart `using-superpowers` injection names explicitly and whose handoff writes to `docs/superpowers/plans/` instead of the memory tree. The rename covers the *skill name* only — the **activity** is still "brainstorming" and the gate is still the "brainstorm gate", so prose using those words was deliberately left alone.
- **An investigation is an artifact; a brainstorm is an activity** — investigations are optional long-form findings artifacts consumed by tasks and `/start`; brainstorms are the dialogue that produces the plan, and investigations archive with their task.
- **Task Contract — success criteria at two levels (v1.5.0).** Plan-tier tasks carry explicit, checkable criteria before execution and the Validator checks exactly that contract — now at **plan** level (`## Success criteria`) *and* **phase** level (a `**Verify:**` line per `### Phase N`). Plan-level-only was the defect: a six-phase plan got one terminal Validator pass, so a phase-2 defect surfaced only once phases 3-6 were built on it. Corollary rule: **a phase whose `**Verify:**` cannot be written is mis-drawn** — too vague to delegate, or really two phases. Phase dependencies are **declared** (`**Depends:**` in the plan, mirrored as `(needs: Pn)` on the `todo.md` checkbox) rather than implied by list order, because `todo.md` is what actually gets read on resume and after compaction; unannotated phases are independent and fan out in parallel. The decomposition rule itself lives inline in `/new-plan` Step 3.5 (a phase = one executor delegation, with split/merge/ordering/checkpoint rules) — **deliberately not** a reference to `superpowers:writing-plans`, which would bind this pipeline to a cached plugin version this tree cannot gate, and whose TDD step-loop is the wrong shape for Terraform/GitOps verification. Two external planning skills (`addyosmani/planning-and-task-breakdown`, `mattpocock/to-tickets`) were evaluated and **both rejected** — they write plans into the target repo, and ticket-per-phase publishing fights the capped thin-record task `summary`. Findings extracted instead; full comparison in the archived `planning-decomposition-seam` investigation.
- **Multi-git-provider support** — repository provider is inferred from the remote host, and PR/repo tooling routes through GitHub, Bitbucket, or Azure DevOps while preserving the no-merge guardrail.
- **Skills owned by memory, symlinked into harnesses** — skills live in memory-owned stores and runtime skill directories receive symlinks from `scripts/link-skills.sh`.
- **Both plan entry points converge on one task-linking step — SHIPPED 2026-09-10 ([PR #104](https://github.com/seyio91/ai-memory-system/pull/104), `44a8b37`).** `/new-plan` was a second entry into plan-tier work that skipped the task lifecycle (8 of 10 live plans carried no `task_ref`, and nothing detected it). Three layers, deliberately chosen so each covers what the others structurally cannot: (1) **one shared source** — `scripts/partials/task-link.md` injected into `commands/new-plan.md` and `commands/start.md`, with a drift gate comparing each carrier's block byte-for-byte, so the two commands cannot diverge; `apply-partial.sh` gained a `--file` target mode (with `MEMORY_DIR` containment) to carry it beyond skills. (2) **a trigger at authoring time** — `--task <ref>` / `--no-task`, mutually exclusive, with one ask when neither is given; linking runs *after* the Goal is drafted, because the summary pushed to the backend must be the real Goal. (3) **a detection rule** — lint rule 12 flags a live plan with no `task_ref`, and `task_ref: none` is the explicit plan-only marker that makes "deliberately unbacked" distinguishable from "forgot". Rejected on the record: backlog title-similarity matching (fuzzy matching in prose no test can gate, and a wrong match silently links the wrong ref); `/new-plan` referencing `/start`'s step by prose (a renumber silently breaks it); a lint rule with no opt-out (plan-only stops being possible and 8 legacy plans become permanent noise). **`/new-plan` stays active-project-scoped** — a cross-project `--task` aborts and redirects to `/start`, which places the plan in the task's own project.
- **The drift gate's carrier count is hardcoded on purpose.** Marker-based discovery fails **open** on deletion — a carrier that lost its block simply drops out of the list and the loop checks what remains. The literal `assert_eq "2"` is the only thing catching total block loss. Bump it when adding a carrier; making it dynamic silently removes deletion detection. A comment at the assertion says so, because this is exactly the shape a later reader "cleans up".
- **Skill subsystem — validation + on-request self-rating; no write boundary.** Skills have schema validation and optional self-rating, but no declared write-boundary mechanism; execution policy and the validator are the enforcement layers.
- **Skill source model** — authored skills are local, remote skills are manifest-declared and lock-pinned, skill state lives under a separate data root, and enumeration is centralized across source roots.
- **Doc-vs-code gate — the `docs/scripts.md` env-var table is machine-checked** — documented script environment variables are checked against code and transitive sourcing paths; the gate is scoped to symbol drift, not semantic prose.
- **A control is not trusted until it has been watched to fail.** Controls must be mutation-tested or otherwise observed failing on known defects before their green result is trusted.
- **Executable tests cannot gate a command whose logic is prose — only a live exercise can.** Slash commands are natural-language instructions an agent follows, so no test in `scripts/tests/` executes them. `/plan-archive` shipped with Step 5 saying "skip to Step 8" twice, which skips Step 7 — the plan move itself — breaking the *default* path (no linked investigation) while the full suite stayed green and its rule-10 lint check passed mutation testing in both directions. Live-exercise every prose command on its **most common** path, not just its interesting one.
- **Knowledge lifecycle** — working memory matures into domain/project memory and, when reusable enough, into packaged skills.
- **Derived state snapshot (`/state`)** — `/state` is an on-demand derived projection of active work across projects and is never auto-injected.
- **Project categories + activity report** — projects may carry one flat category for grouped `/state` and `/activity` reporting; the report groups plans by creation window.
- **Durable memory names artifacts; it does not store their paths** — durable memory references artifacts by name, not path; only live machine-consumed fields may hold paths.
- **Wikis document existing system components, not plan references** — `wikis/` records durable system components; comparison, triage, and backlog material belongs to plan inputs and archives after use.
- **This meta-project is tracked in-repo** — `projects/ai-memory` is the tracked dogfood project for this repo, with durable memory artifacts versioned and `working.md` left local-only.
- **Commit route is decided by *what* changed, not how big the change is: memory tree vs shipped system.** **Housekeeping** — anything under `projects/` (todos, plans, investigations, `memory.md`, archive moves) — is bookkeeping *about* work, changes no behavior, and goes **directly to `main`, no PR, no CI**. **System changes** — `scripts/`, `harnesses/`, hooks, `install.sh`, `docs/`, `.github/`, skills — ship to consumers and require a **branch + PR**, regardless of how small the diff looks. A one-line hook edit is a system change; archiving five plans is not. Size is not the axis, and "it's only a doc" is not an exemption: `docs/` is shipped. **The tracked `domain/` files are system changes and need a branch + PR** (decided 2026-07-18, after routing one to `main` and reverting it). `/domain/*` is gitignored *except* `_template.md`, `agent-tooling.md`, `codex.md` (`.gitignore:29-32`) — those three ship in every release tag, so **users read them**, and content a user consumes is reviewable regardless of whether anything executes. The axis is **does it reach users**, not "does it run": a wrong domain entry teaches a wrong model to every consumer, which is exactly the harm review exists to catch. Untracked `domain/` files are personal and need no route at all.
- **Open-sourcing: remove content going forward, never scrub** — the public transition removes live personal/client content from current tracked files but does not rewrite published history or archive audit trail.
- **Per-environment config loader; instance config never in tracked memory** — instance choices live in gitignored `config.local.sh`, with tracked examples only; scripts and orchestration read runtime config from there.
- **Harness-agnostic, manifest-driven engine** — harnesses are registered by manifests with delivery and execution faces; `install.sh` drives shared installation through manifest data and common content formatting.
- **Codex adapter — hook-base, chunked (the Antigravity model)** — Codex uses a hand-owned static base plus live chunked hook injection for dynamic memory; `codex-mem.sh` remains only as the executor wrapper.
- **Antigravity harness — hook archetype, live injection + enforced executor** — Antigravity uses hook-time XML memory injection, an enforced guarded executor mode, and its own memory-aware statusline.
- **Hook layer — declarative, manifest-driven, shared where isomorphic** — hook roles are declared in manifests; Claude and Codex share behavioral hook scripts where their contracts match, while harness-specific registration remains allowed.
- **Hook layer — share the isomorphic, special-case the divergent; don't abstract over a bounded harness set.** Shared hook abstractions stop at genuinely common contracts; divergent harnesses keep thin local paths rather than forcing a universal adapter.
- **Versioned release channel — a git tag IS the release; no zip, no separate engine root** — consumers sync to stable tags or dev refs; migrations are forward-only/idempotent and releases are guarded, resumable tag cuts.
- **Release automation — SHIPPED; changelog is written per-PR, never drafted at release time.** Each PR drops a `changelog.d/<id>.<kind>.md` fragment (`breaking`/`feature`/`fix`/`upgrade`); `assemble-changelog.sh` turns them into a CHANGELOG section and derives the version from the kinds. `release-pr.yml` opens/refreshes the Release PR, merging it is the human gate, and `release-publish.yml` then runs `release.sh --publish` to tag and publish. **The rejected alternative matters:** having a model write the changelog *in CI* was considered and refused — by release time the *why* is gone, so it reconstructs intent from commit subjects, which is exactly where hallucinated release notes come from. Model drafts the fragment while the reasoning is live; the suite enforces the invariant (`test_upgrading_doc.sh`: every `migrations/<v>-*.sh` has a matching `UPGRADING.md` section). A model is deliberately kept **off** the CI critical path — no API key in CI, no nondeterminism in a publish step. Also decided: **build no changelog/upgrade-note skills** — a fragment is a by-product of the PR step, not a capability. Full reasoning in the archived `release-automation` plan + wiki.
- **CI skips the suite for the four root community files, via a gate job — never `paths-ignore` (decided 2026-07-20, PR #91).** Exempt: `README.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`. Verified to have zero test surface — `lint-memory.sh` globs only `domain/*.md` and `projects/*/…`, `check-docs` parses only `docs/scripts.md`, and the tests matching `README` use it as a sandbox fixture filename. **`docs/**` is deliberately NOT exempt**: `docs/scripts.md` is machine-checked and `docs/` ships in every release tag. Three constraints hold this shape and must survive any future edit: (1) **gate job, not `paths-ignore`** — the latter skips the workflow entirely, reports *no status*, and deadlocks a required check under branch protection (a stated goal); (2) **fail closed** — empty diff or failed fetch runs the suite; (3) **anchored match** (`grep -vxE`) — unanchored, `docs/README.md` becomes exempt and the suite is skipped on a real docs change; this was mutation-tested and is the failure mode to check first. Growing the exemption list requires re-running the verification, because a rotting list fails *open*. **My first recorded version of this decision (same day) said path filters were a deliberate non-goal — that was superseded within the hour after the user pushed back twice; the "markdown is not inert" argument is about `docs/`, and does not defend running a suite that provably reads nothing.**
- **The tests badge must carry `?event=pull_request` (fixed 2026-07-20, PR #89).** A workflow badge with no query params resolves to the latest run on the **default branch**, but `tests.yml` fires on `pull_request` only (#78 removed the push trigger), and a PR run's `head_branch` is never `main`. The badge therefore froze on run `29652600768` — a billing refusal from 2026-07-18 — and no future run could supersede it. **Removing a push trigger silently freezes that workflow's badge forever;** re-check the badge whenever a trigger changes.
- **Initiative layer + consultation triggers — SHIPPED 2026-09-09 ([PR #102](https://github.com/seyio91/ai-memory-system/pull/102), `b3283da`).** Root-level `initiatives/<slug>.md` (peer of `projects/`/`domain/`): append/supersede decision stream, Targets with slug ids, explicit open/close, breadcrumb-only injection, derived status. Guard and reusable Target templates deliberately deferred until observed need. **The layer's own falsification criterion fired on first real use** — three cross-repo decisions reached plans, runbooks and project memory but never the stream, and nothing detected it; verdict *trigger failure, not refutation*, so the same PR carries the B+C+D composition: (1) snapshot staleness at `initiatives/.state/<slug>.snapshot`, persisting until a stream append or `--ack` — it never self-silences, because a warning that clears itself recreates the invisible-omission shape it exists to catch; (2) an **exception-only** `<memory:initiative-alert>` on the session-start payload, deliberately not `@memory`/post-compact and never an ambient status table, because the evidence pointed at decision *timing*, not visibility; (3) the decision-time question at `/checkpoint` and phase completion; (4) the **stream-first rule** — the stream is the record, plan/runbook/memory entries are projections citing its id. Reuse of the checker is **by subprocess, not by sourcing**, so a path that must fail open cannot inherit its side effects. Known limitation, named rather than hidden: the hook guard is fail-open, so a crashed checker is silent and reads exactly like "nothing is stale". The composition's own falsification test is armed in `working.md` → `## Open threads`.
- **Non-goals:** no runtime deny hook enforces `todo.md`; `install.sh` is the supported agent-runnable bootstrap.

## Known Constraints / Gotchas
- **`skills_with_partial()` returned the last `grep`'s status, so `apply-partial.sh --all` died silently under `set -e` — broken at HEAD since it was written, found 2026-09-10 (PR #104).** The function's main branch ended on `grep -Fq … && basename`, making a *lister* into an accidental *predicate*: it returned 1 whenever the alphabetically-last skill wasn't a carrier, and the caller's `carriers="$(…)"` assignment then aborted the script under `set -euo pipefail` — **exit 1, empty stdout, empty stderr.** It stayed invisible because every partial until `task-link` had at least one skill carrier; a partial carried *only* by commands made the list empty and exposed it. The sibling `if [ -n "$dir" ]` branch in the same function already had the `return 0` the main branch lacked — **that asymmetry is the tell.** Third instance of the house pattern (`rtk ls` locale, `git check-ignore` on tracked paths): **a failure that is silent AND exits non-zero reads as "nothing to do" and gets attributed to whatever looks suspicious nearby.** Fixed at root in `scripts/_lib.sh`, not at the call site.
- **A sandbox test can pass while the real path dies, when the fixture cannot produce the empty case.** `test_apply_partial.sh`'s `--all re-syncs command carrier` assertion was green in its sandbox while the identical call died on the real tree — the fixture never yielded *zero* skill carriers. When a test covers "walks a list", seed the empty list explicitly; it is the case most likely to be both untested and fatal.
- **The live exercise of a prose command is not ceremony — it found two defects a green suite could not (2026-09-10).** Walking `/new-plan`'s **default** (unflagged, plan-only) path exposed both the `--all` bug above and an ordering error in the freshly-authored partial: `Stop here for task_ref: none` sat above Step L5, so choosing plan-only skipped the backend calls *and* the `todo.md` entry, dropping plan-only work out of execution tracking entirely. Restates the standing rule with fresh evidence — **live-exercise every prose command on its most common path, not just its interesting one** (`/plan-archive` shipped the same class of bug in 2026-07).
- **This repo IS under git, but personal content is `.gitignore`d.** The tracked source tree is distributable, personal/runtime memory is ignored, and only the `ai-memory` meta-project is intentionally versioned.
- **Scripts target macOS `bash` 3.2** — scripts must remain compatible with Bash 3.2 and resolve the memory tree through `MEMORY_DIR`.
- **The housekeeping-goes-to-`main` route does NOT survive a feature branch that created the housekeeping artifacts (learned 2026-09-09, PR #102).** Two independent reasons, both only visible by checking rather than reasoning: (1) most of what looks like housekeeping is **gitignored** — `/projects/*` except `ai-memory`, and `/initiatives/*` — so sibling project memories and live initiative instances are local-only and have no commit route at all; (2) archiving an investigation that was *added on the branch* cannot happen on `main`, which has never seen the file. Check `git check-ignore --no-index` and `git diff --name-only origin/main..<branch>` before planning a split; when the artifacts are branch-born, the housekeeping rides the branch and the rule simply does not apply. Related trap avoided in the same pass: local `main` was **7 commits behind `origin/main`**, so a switch to route housekeeping would have landed on a stale tree mid-session.
- **`archive/` is never read unless the user explicitly asks** — archive content is audit trail, not working context, and is not deleted during reorganization.
- **Frontmatter is the contract** — catalog, lint, and regeneration depend on valid frontmatter; templates are excluded.
- **Working memory is per-project; its content rides the full payload injected once per session (and on `@memory`/post-compaction), NOT every prompt.** Keep `working.md` short; concurrent sessions on the same checkout are last-write-wins.
- Slash commands are indexed at session start — a new command needs a session restart to autocomplete.
- Oversized hook stdout is routed to a `<persisted-output>` file with a 2KB preview, but bloated `working.md` still expands full-payload injection.
- **For a security control, a green test suite is where validation STARTS, not ends.** Security controls need adversarial validation beyond the normal suite; false-positive fixes must be checked for false negatives.
- **A test file the runner's glob doesn't reach is silently ungated — the suite reports green and proves nothing.** New test locations must be wired into the runner or they are not part of the gate.
- **A `set -e` test that dies mid-run reports a bare rc=1 with no reason, no failing assertion, and no summary — every assertion after the death point is ungated while the file still *looks* like one failing test.** Wrap fallible checks in `set +e` / `rc=$?; set -e` so failures reach the reporter. Corollary: an assertion that hardcodes a value the code derives from config rots the moment config changes — derive the expectation from the same source (`test_install_harness.sh` matched 0 entries and hid 106 of 143 assertions from `742f083` until 2026-07-18). "Fails at HEAD too" establishes *not mine*, never *not related* — always trace the cause.
- **A recorded measurement is where planning STARTS, not ends — re-measure before you act on it, especially when it is the fact that justifies the work.** Planning baselines must be re-derived before execution, and each proposed control must be matched empirically to the bug class it claims to catch.
- **Codex execpolicy** `decision` must be `"forbidden"`; invalid values fail at `codex exec` time, and executor runs outside git repos need `--skip-git-repo-check`.
- **[FIXED in rtk 0.44.2 — revalidated 2026-08-04: `rtk ls` returns correct output under `nl_NL`/`en_GB`/`de_DE`/`fr_FR`/`en_US`/`C`. Keep the `LC_ALL` export (harmless) but don't prescribe it as the fix elsewhere without re-reproducing.]** **ROOT-CAUSED (2026-07-18): the phantom-empty `ls` was never TCC — it is `rtk ls` returning nothing on a non-`en_US` locale.** `rtk 0.38.0`'s `ls` exits **0 with empty stdout and empty stderr** whenever `LANG`/`LC_ALL` is anything other than `en_US.*` or `C` — verified on freshly-created dirs in both orders (`nl_NL`, `en_GB`, `de_DE`, `fr_FR` → empty; `en_US`, `C` → correct), so it is locale, not caching or ordering. This box runs `LANG=nl_NL.UTF-8` (hence the Dutch `mrt`/`jun` in `ls -l`), and the Claude hook rewrites bare `ls` → `rtk ls`, so **every bare `ls` silently returned empty**. Note `en_GB` also fails: the split is `en_US`/`C` vs everything else, not English vs non-English. Fixed here by `export LC_ALL=en_US.UTF-8` in `~/.zshenv` — **not** `LC_ALL=C` (byte-mode would mangle the non-ASCII this tree is full of), and **not** `config.local.sh`, which no shell profile ever sources. Escape hatch if it recurs: `rtk proxy <cmd>` bypasses the filter. Blamed on TCC for weeks and "fixed" by relocating the tree, which of course changed nothing — **a failure that is silent AND exits 0 will be misattributed to whatever looks suspicious nearby; bisect the environment instead of trusting the plausible story.**
- **`ls`/glob output is not evidence for a count or an absence claim — corroborate with `find` or `git ls-files`.** Independent of the rtk bug above, this is the durable habit: the failure reads as a real result, so it fabricates confident wrong conclusions in both directions — absent-when-present *and* present-when-absent.
- **A truncating pager on test output hides scope, and the per-file listing is not the coverage signal — the summary counter is.** `run-tests.sh` emits >60 lines, so a habitual `| tail -60` silently drops the alphabetically-earliest files (16 of 48 on 2026-07-18) and the surviving listing looks complete. Reconcile the printed file count against the `tests: N passed` total before calling a run full; the banner absence (`SELECTED RUN`, `NOT A FULL RUN`, `UNMAPPED`) is necessary but not sufficient.
- **`link-skills.sh` only ever visits skills that still exist, so a link whose source vanished is never revisited** — a rename or a tree move strands it indefinitely (`dashboarding`, `tempo` survived both, dangling from 30 jun to 18 jul 2026). The prune pass therefore matches on **shape** (dangling + target directly under `skills/` or `.skill-cache/` + basename equals link name) rather than against the *current* store roots, because a moved tree leaves links pointing at a root that is no longer configured.
- **A git worktree on this self-referential meta-project forks the memory tree, but `MEMORY_DIR` stays pinned to the main checkout.** In `ai-memory`, plan/todo/memory bookkeeping stays canonical in main; worktrees are for engine code only unless isolated with their own `MEMORY_DIR`.
- **In this tree a branch switch is a live downgrade of the running harness, not a source checkout change — and a stale local `main` makes it silent (2026-09-08).** The instance was detached at `v1.4.0` with `AI_MEMORY_CHANNEL="release"` (contradicting this file, which claimed `dev` — the config had won and nobody noticed). `git switch main` landed on a **local `main` 182 commits behind `origin/main`**, at the v1.1.0 cut, instantly rolling back `harnesses/claude/CLAUDE.md`, `commands/`, `scripts/`, and `todo.md` *while the session was using them*. Git's only warning is a conversational `Your branch is behind … can be fast-forwarded` line printed **after** the tree has already moved. Rules that follow: (1) go to the remote ref, not the branch name — `git switch -C main origin/main`, or `git fetch && git merge --ff-only origin/main` immediately after; (2) **check the channel before authoring** — a `release`-pinned instance is a consumer and `/sync-system` will yank it back onto a tag mid-work; (3) personal files (`identity.md`, `orchestrator.md`, `config.local.sh`, `projects/*/memory.md`, `working.md`) are gitignored and survive the switch untouched — only the *engine* rolls back, which is exactly why the damage is easy to miss; (4) after any version hop, re-run `install.sh` — `UPGRADING.md` documents deletions (e.g. `arm_recompact.sh`) whose stale hook entries only that sweep removes.
- **`git check-ignore` short-circuits on TRACKED paths and reports "not ignored" WITHOUT reading `.gitignore` — so any test asserting a tracked file is un-ignored passes for free (found 2026-09-08).** `test_brainstorming_skill_tracking.sh` guarded the `!/skills/brainstorming/**` negation that keeps the bundled skill tracked under a blanket `/skills/*` ignore. Deleting the negation outright did **not** fail it: the file is always tracked, so `check-ignore` never consulted the rules. Fixed with `--no-index`, then mutation-tested in both directions. Two lessons: (1) `--no-index` is mandatory whenever the *rules* are what's under test, not the current index state; (2) this is a third instance of the house pattern — **git plumbing that consults the index before the working-tree rules answers a question you did not ask**, exactly like the `ls`/glob and `branch --contains` entries. A renamed skill dir also silently re-ignores everything new inside it (e.g. the skill's own `self-rating.md`) while the already-tracked `SKILL.md` survives, which is why the breakage is invisible until a second file appears.
- **A suite that inherits the developer's global git config is not hermetic, and CI cannot tell you so (found 2026-09-08).** With `commit.gpgsign=true` / `tag.gpgsign=true` and an SSH key behind the 1Password agent, fixture repos fail to sign: **44 assertions across `test_release.sh` (13), `test_sync_channels.sh` (26) and `test_assemble_changelog.sh` (5)** fail with `fatal: no tag message?` and `fatal: failed to write commit object` — errors that read as release-logic bugs, not environment. All three go green under `GIT_CONFIG_COUNT` overrides disabling signing. **CI passes clean on both runners with no workaround**, because CI has no signing config — so a green CI is evidence that CI's environment is bland, *not* that the suite is hermetic, despite the runner's own `(hermetic)` banner. The same agent intermittently breaks real `git-cli commit` too (`agent returned an error`, `failed to fill whole buffer`); a retry then succeeds **unsigned**, silently. Tracked as `isolate-test-fixtures-from-the-developer-s-global-git-config`.
- **`git branch --contains <ref>` answers "which branches contain this commit", not "which branches exist" — a stale local branch is absent from the output precisely because it is stale.** Reading its silence as "no local `main`" is what routed the switch above onto a 182-commit-old branch. Same failure family as the `ls`/glob entry below: the output reads as a real answer to a question it was never asked. Corroborate branch existence with `git branch --list` or `git for-each-ref refs/heads/`, and compare against `origin/<branch>` with `git rev-list --left-right --count` before switching.
- **The `1/1` no-chunking default is fine on `copilot` and `antigravity`; only Claude needed chunking (validated live 2026-07-18).** Neither manifest declares `session_chunks`/`inject_chunks`, so both deliver the whole base as one message — copilot 52,780 chars (its `md` path renders an extra `domain` section) and antigravity 46,284 (`xml`) — and both were confirmed to load after a `/clear`. The missing keys are therefore *not* a latent copy of the Claude bug: Claude's ~10,000-char `additionalContext` cap is the outlier, not the norm. Caveat: point-in-time at ~50KB, and nothing emits a marker if either later crosses a cap as memory grows — that failure would be silent, the same shape as Claude's. Verify the payload's **tail** (`working` renders last in both formats), never just that memory "appeared": Claude's bug still showed an `identity.md` preview, so a presence check passes while four of five sections are missing.
- **Registration order is not delivery order — Claude runs same-event hook entries concurrently and concatenates by completion.** Codex delivers in registration order; Claude does not (observed 2026-07-18: entries registered 1..12 arrived 2,3,4,1,5). Any payload fanned across N hook entries must be self-ordering — slices carry a `<memory:chunk index of>` envelope — because line-boundary slicing means an out-of-order chunk bisects a content block. A per-harness behaviour verified on one harness must not be assumed for another.
- **Codex `exec` (headless) fires `SessionStart(source=startup)` AND injects its `additionalContext` into model context — verified by live probe (2026-07-16, codex 0.144.4; floor 0.135.0).** Startup injection is proven for headless Codex; compaction survival is still unproven and must not be assumed.
- **Notion provider:** Notion can add/reorder select/status options but cannot rename/delete them; non-interactive routing requires credentials and provider env in `.zshenv`.
- **Notion refs are ALWAYS the full page UUID, never the 8-char prefix.** Short refs are ambiguous and API-invalid; local-provider slug refs do not change this Notion rule.
- **Plan-mode plan path:** plan-mode artifacts belong under `projects/<active>/plans/<name>.md`, not the harness default plan directory.
- **`config.local.sh` beats the environment.** Values exported from gitignored `config.local.sh` override process env, so instance channel/provider/executor changes must be made there.
- **`git tag -a -m` strips every line starting with `#`** — annotated release tags must preserve markdown messages with verbatim cleanup/file input. `git tag -l -n` reformats the message and hides the loss; only `git cat-file tag` shows the raw object.
- **`--to <branch>` checks out that ref as-is and does not fast-forward it.** Use an up-to-date remote ref when dogfooding or syncing to a branch.
- **`v1.0.0` is a trap tag — never point an instance at it.** It predates `identity.md` untracking and can clobber personalized identity data; `v1.1.0` is the first safe release tag.
- **Docs rot within hours when phases ship serially.** Runtime changes require rereading command docs as well as reference docs.
- **A tracked `identity.md` bricks the release channel.** User-editable files must not be tracked; untracking a previously tracked file can delete local data during checkout transitions.
- **A git tag ships a whole tree, and there is no build step to filter it.** Under tag-based distribution, tracking a file publishes it in every release; `.gitattributes export-ignore` is no defence — `git archive` honours it, `git clone`/`git checkout <tag>` do not.
- **A GitHub force-push does not remove anything.** GitHub-controlled PR refs can preserve scrubbed history; deleting/recreating the remote is the only complete removal path.
- **`domain/<topic>-cache/` subdirectories are invisible to both the catalog and git.** `regenerate-index` globs top-level `domain/*.md` only (`-maxdepth 1`), and `/domain/*` is gitignored — so a path-addressed cache like `domain/terraform-module-cache/` (one file per module, keyed on short name) is local, untracked, and looked up by direct path. Never reindex after writing one; it will not appear.
